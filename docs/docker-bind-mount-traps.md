# Docker bind-mount 单文件陷阱

> 场景：容器以 `-v <宿主机文件>:<容器路径>` 挂载**单文件**（如 /etc/ 下的
> hccl_rootinfo.json、hccn.conf）后行为诡异；或需要**热更新**一个已被挂载的文件。

## 规则一：挂载不存在的宿主机文件，docker 会造出同名目录

bind-mount 源是**文件**且宿主机上**不存在**时，docker 不会报错，而是在宿主机
上自动创建一个**同名空目录**并挂载之。容器内该路径因此是目录而非文件，应用
读到的"配置文件"为空，报解析失败——错误信息指向应用层，极具迷惑性。

```bash
# 症状核对：容器内该路径是目录 → 宿主机源十有八九被 docker 造了目录
docker exec <container> ls -la /etc/<配置文件>   # 行首是 d 即目录
ls -ld /etc/<配置文件>                           # 宿主机源同样是 d，且为空
```

**判别口诀**：配置文件"读不出来/内容为空"时，先查宿主机源路径是文件还是目录，
再怀疑应用。

## 规则二：修复要走 overlay2 手术 + 重启容器

误生成的目录位于容器可写层，直接 `docker start` 无法清除（挂载点类型已定）。
修复顺序：

```bash
# 1. 找到容器可写层 UpperDir
U=$(docker inspect --format '{{.GraphDriver.Data.UpperDir}}' <container>)
# 2. 删除误生成的目录（只删这一项，勿动其他内容）
rmdir "$U/etc/<配置文件>"
# 3. 宿主机把真实文件补到源路径，再启动容器
docker start <container>
```

## 规则三：热更新挂载文件必须保 inode——`cat >` 而非 `cp`

bind-mount 挂的是**inode**：

| 写法 | inode | 运行中容器看到 |
|------|-------|----------------|
| `cat > file` / `tee file`（原地写） | 不变 | **实时更新**，免重启 |
| `cp src file` / `mv` 覆盖 | 更换 | 仍是旧内容，直到容器重启 |

给运行中容器的挂载文件换内容，一律用原位写：

```bash
cat /path/to/new.json > /etc/<被挂载文件>    # 宿主机执行，容器内立即可见
```

生成类工具（输出到临时文件再落位）注意最后一步换成 `cat >` 而不是 `cp`。

## 组合场景：为容器补一个缺失的身份配置文件

典型流程（以 HCCL rootinfo 类"每机唯一"的配置为例）：宿主机生成正确文件 →
确认旧挂载没把路径变成目录（规则一/二）→ `cat >` 原位写入（规则三）→ 容器内
校验内容 → 重启依赖它的进程。
